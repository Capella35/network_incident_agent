# evals/cases/

Recorded cases with known right answers: the fixed inputs the system is scored on. How they are scored: `specs/09-evals.md`. Measured numbers: `../results-log.md`.

**Status:** empty. Fault scenarios arrive in Milestone 2, agent questions in Milestone 5. The formats below are the **(default)** plan; each milestone plan may refine them with a recorded reason.

## What goes here

| Folder (planned) | Case = | Right answer | Arrives |
|---|---|---|---|
| `faults/` | One injected fault: type, root node, onset, duration, magnitude, seed (SYNTHETIC) | Must be detected; matched incident's root node, category, severity, team | M2 |
| `reports/` | Noisy report templates, split into training and **unseen** test templates (SYNTHETIC) | The incident's true labels | M4 |
| `agent/` | One investigation question about an incident, incl. negative, no-fault, and prompt-injection cases | IDs / enums / ID sets, graded exactly (no LLM judge) | M5 |

Planned format: one JSON Lines file per split (`validation.jsonl`, `test.jsonl`), one case per line with `case_id`, `kind`, `input`, `expected`, and `source` (generator, seed, config hash).

## Rules
- **Cases are generated by script** from the injector's ground truth and the topology (`specs/01-domain-model.md`), never written by an LLM, and never edited by hand after freezing.
- **The headline set is frozen** (≥ 20 agent questions; Definition of done). Changing it needs a reason in `DECISIONS.md` (Rule 5).
- **Test-week cases are generated once and not opened before the final evaluation** (Rule 7). Only validation cases are used while building and tuning.
- **Ground truth stays in evaluation** (Rule 6): only `src/evaluation/` reads these files. Detectors, the correlator, the classifier, and the agent never do.
- **Only synthetic IDs and labels**, no raw Milan rows (Rule 3). Committed cases are checked by the same pre-commit hooks as code.
